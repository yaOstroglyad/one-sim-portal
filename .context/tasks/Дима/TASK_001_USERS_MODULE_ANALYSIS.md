# Task 001: Анализ структуры модуля Users

## Цель задачи
Изучить архитектуру модуля Users, понять взаимосвязи компонентов и создать визуальную диаграмму зависимостей.

## Описание
Модуль Users - это типичный CRUD модуль в Angular приложении. Ваша задача - разобраться в его структуре и документировать архитектуру.

## Этапы выполнения

### Этап 1: Изучение структуры файлов

#### 1.1 Структура модуля Users
```
src/app/views/users/
├── create-user/
│   ├── create-user.component.ts      # Компонент создания пользователя
│   ├── create-user.component.html    # Шаблон формы
│   ├── create-user.component.scss    # Стили
│   ├── create-user.component.spec.ts # Тесты
│   └── create-user.utils.ts         # Утилиты для формы
├── users-data.service.ts            # Сервис для API запросов
├── users-table.service.ts           # Сервис конфигурации таблицы
├── users.component.ts               # Главный компонент
├── users.component.html             # Шаблон списка
├── users.component.scss             # Стили
├── users.module.ts                  # Модуль
└── users-routing.module.ts          # Роутинг
```

#### 1.2 Что изучить в каждом файле

**users.module.ts**
- Какие компоненты объявлены
- Какие модули импортированы
- Какие сервисы предоставляются

**users-routing.module.ts**
- Какие роуты определены
- Какие компоненты загружаются

**users.component.ts**
- Какие сервисы инжектируются
- Какие методы жизненного цикла используются
- Какие данные передаются в шаблон

**users-data.service.ts**
- От какого класса наследуется
- Какие методы API реализованы
- Какие endpoints используются

**users-table.service.ts**
- Как конфигурируется таблица
- Какие колонки определены
- Какие фильтры доступны

### Этап 2: Создание диаграммы

#### 2.1 Инструменты для создания диаграммы
Можно использовать любой из:
- draw.io (бесплатный онлайн)
- Lucidchart
- PlantUML
- Miro/Figma
- Даже PowerPoint или Google Drawings

#### 2.2 Что должно быть на диаграмме

**Основные элементы:**
1. **Модули**
   - UsersModule
   - UsersRoutingModule
   - SharedModule (и другие импортированные)

2. **Компоненты**
   - UsersComponent
   - CreateUserComponent
   - GenericTableComponent (из shared)
   - FormGeneratorComponent (если используется)

3. **Сервисы**
   - UsersDataService
   - UsersTableService
   - AuthService
   - HttpClient

4. **Связи**
   - Импорты модулей (пунктирная линия)
   - Инжекция сервисов (сплошная стрелка)
   - Использование компонентов (стрелка с подписью)
   - Наследование (стрелка с пустым треугольником)

#### 2.3 Пример структуры диаграммы
```
┌─────────────────┐
│  UsersModule    │
│                 │
│ declarations:   │
│ - UsersComponent│
│ - CreateUser... │
└────────┬────────┘
         │ imports
         ▼
┌─────────────────┐     uses      ┌──────────────────┐
│ UsersComponent  │──────────────▶│ GenericTable     │
│                 │                │ Component        │
│ - tableConfig   │                └──────────────────┘
│ - loadUsers()   │
└────────┬────────┘
         │ injects
         ▼
┌─────────────────┐   extends   ┌──────────────────┐
│UsersDataService │────────────▶│ DataService<User>│
│                 │             └──────────────────┘
│ - list()        │
│ - createUser()  │
└─────────────────┘
```
